This is an Expo/React Native mobile app plus its website, built the same way as Belay Buddy (fizzgig17/belaybuddy.app). Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo or React Native API:

1. Read the major version of `expo` in `package.json` (currently 57).
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt and follow its links; never answer from memory.

## Commands

```bash
npx expo install <package>   # ALWAYS instead of npm install: resolves SDK-compatible versions
npx expo start               # dev server
npx tsc --noEmit             # typecheck (run before declaring any task done)
npx expo export --platform web --output-dir dist   # build the website
```

## Branches, builds and environments

- `develop` → dev: belaybuddy-dev Supabase, dev.edcroulette.app, "EDC Roulette Dev" builds.
- `master` → prod: belaybuddy-prod, edcroulette.app, production builds.
- Builds never start on their own: `[ios]` in the last commit message starts an Xcode Cloud build (docs/xcode-cloud.md); `[android]` starts the Android build. Every push to develop/master deploys the website.
- `ios/` and `android/` are generated by `expo prebuild` and not committed, except `ios/ci_scripts/` (rewritten by plugins/with-xcode-cloud.js). Configure native behavior in `app.json` and config plugins.

## Code layout

- Routes in `src/app/` (Expo Router). Components, hooks and libraries outside it.
- Styling: plain `StyleSheet` + `src/constants/theme.ts` (no NativeWind). Use `ThemedText`, `Screen`, `Card`, `Button`, `ChipGroup`.
- State: React context providers (`src/lib/gear.tsx`), no Zustand.
- The free tier's data lives only on the phone: `src/lib/db.ts` (expo-sqlite, numbered migrations; never edit a shipped migration), photos in `src/lib/photos.ts`.
- The website is the same code: `*.web.tsx` files replace phone-only pieces. Expo Router bundles every route for the web, so anything that imports `expo-sqlite` must have a `.web` stand-in (see `lib/gear.web.tsx`, `lib/local-database.web.tsx`), and app-only screens have `.web.tsx` redirects home.

## Backend (shared with Belay Buddy)

EDC Roulette uses Belay Buddy's Supabase projects. Everything EDC owns is in the `edc` schema, the `edc-gear` storage bucket and Edge Functions named `edc-*`. Schema changes are new numbered files in `supabase/edc/migrations/` (see `supabase/edc/README.md`); never use `supabase db push` here. Never change Belay Buddy's `public` schema from this repo.

## Product rules

- Free tier: no account, at most 20 items and 4 slots (`src/lib/limits.ts`), all data on the phone.
- Premium ($1.99/month) requires sign-in; only premium accounts may write cloud data (enforced by row-level security).
- It's a randomizer, not gambling: no betting, wagering, prizes, coins or casino language anywhere, including store metadata. Never sell spins or random rewards.
- Keep `src/content/legal.ts` (privacy, terms, support, data deletion) in step with what the app really does; update it before a feature that sends data anywhere ships.
